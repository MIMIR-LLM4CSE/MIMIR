You are preparing a pull request.

Steps:
1. Summarize the problem and solution.
2. List key changes.
3. Mention tests added or updated.
4. Note potential risks or follow-ups.

Rules:
- Do NOT introduce new changes.
- Focus on clarity and reviewer experience.
- Assume the reviewer is familiar with the codebase.

Output should be ready to paste into a PR description.
